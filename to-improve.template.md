## Priority 1: Security & Secrets

### Hardcoded Passwords in Zigbee2MQTT

- **Issue**: `zigbee2mqtt/configuration.yaml` may contain a hardcoded MQTT password.
- **Risk**: If this repository is ever made public or shared, the credentials are exposed.
- **Fix**: Move the password to `secrets.yaml` and reference it as `!secret mqtt_password` in the Zigbee2MQTT config.

### HTTP IP Ban Disabled

- **Issue**: `configuration.yaml` may have `http: ip_ban_enabled: false`.
- **Risk**: While `trusted_proxies` may be configured, disabling IP bans entirely removes a layer of protection against brute-force attacks from non-proxied sources.
- **Fix**: Consider enabling `ip_ban_enabled: true` unless it interferes with a reverse proxy or Cloudflare tunnel.

## Priority 2: Architecture & Organization

### Split `automations.yaml`

- **Issue**: As `automations.yaml` grows beyond ~500 lines, navigation and merge conflicts become difficult.
- **Fix**: Use `automation: !include_dir_list automations/` and split the file into logical directories (e.g., `automations/kitchen.yaml`, `automations/bedroom.yaml`, `automations/system.yaml`).
- **Note**: This requires moving each automation to its own file or grouping them by room/category.

### Extract Templates to Separate Files

- **Issue**: The `template:` section in `configuration.yaml` may grow large with complex Jinja2 logic.
- **Fix**: Move template sensors and binary sensors to `templates.yaml` using `template: !include templates.yaml`.

### Underutilized `scripts.yaml`

- **Issue**: Many automations contain inline sequences that could be reusable scripts.
- **Fix**: Extract common sequences (e.g., "TTS Announcement with Volume Boost/Restore") into named scripts to reduce automation complexity and enable reuse.

### Powercalc Configuration

- **Issue**: Powercalc sensors defined directly in `configuration.yaml` become harder to manage as more devices are added.
- **Fix**: Move to `powercalc.yaml` or a `powercalc/` directory for better maintainability.

## Priority 3: Documentation & Maintenance

### `temp/` Directory Cleanup

- **Issue**: The `temp/` directory may accumulate old notes, plans, and one-off scripts.
- **Fix**: Archive or delete files that are no longer relevant. If they contain useful patterns, move them to `patterns/standardize.md` or a dedicated `docs/` folder.

### Entity ID Cleanup

- **Issue**: Entities generated by Zigbee2MQTT often use raw MAC-address-based IDs (e.g., `light.0x00124b00xxxxxxxx`) instead of friendly names.
- **Fix**: Rename entities in HA via Settings → Entities, or add `friendly_name` overrides in `configuration.yaml` `customize:` for better readability in the dashboard and logs.
  - **Caution**: Renaming entities in HA can break existing automations. Always search for old entity IDs in `automations.yaml` and `dashboard.yaml` before renaming.

### Recorder Optimization

- **Issue**: Default recorder settings may accumulate unnecessary history from high-frequency or low-value entities.
- **Fix**: Add `exclude:` blocks in `recorder:` for entities that do not need history (e.g., `sensor.time`, `sensor.date`, intermediate template sensors). Adjust `purge_keep_days` to balance storage vs. history depth.

## Priority 4: Dashboard Enhancements

### Conditional "All Lights Off" Button

- **Issue**: An "All Lights Off" button may always be visible even when no lights are on.
- **Fix**: Wrap it in a `conditional` card that only shows when at least one light is on, reducing visual clutter.

### Climate Card for A/C Control

- **Issue**: A/C units controlled via IR or `input_boolean` may only have a simple button card.
- **Fix**: If a `climate` entity exists (or can be exposed via IR), replace the button with a `custom:mushroom-climate-card` for inline temperature and mode control.
